# 电子宠物 2.0：选蛋、星光培养、升级徽章与兑换

本文件是本次规则的最终说明，优先于 `pet-home-v1.md`、`pet-release-local.md` 等历史版本中的星光小铺说明。交付方式为本地源码包，不声称已提交 GitHub、合并 main 或部署生产。

## 孩子实际能做什么

在“小队世界 → 小伙伴的家”选择一颗蛋。共八种：独角兽、小狗、小兔、九尾狐、小鸡，以及原有的眠眠熊、云朵、太空猫。点击先预览，选定前可以随意比较，不收星光，不设稀有概率，也不抽取付费随机结果。选定后取名、领养并陪伴破壳；一个孩子保留一只主伙伴，不能靠重新领养重复领取奖励。

现有三项问候和离开后准备孵化规则保留；不需要守着计时，不消费加速道具，出生需孩子点开并可重看。基础食物、饮水、梳毛、洗澡、睡觉、普通玩耍和已有本领不收费。没有缺席死亡、逃跑、亲密度惩罚或连续打卡要求。

## 两种可花的资源，一个不可花的进度

- 星光：继续使用现有家庭奖励账本。投入一颗，扣一颗星光，增加一点永久成长。星光获得方式不改变，不把宠物小游戏变成刷积分入口。
- 成长进度：不是新货币。不能购买商品或换回星光，不会因其他消费减少，也不会因离开而退步。
- 徽章：每从一级升到下一级，固定获得15枚；初始1级不赠送15枚。跨越多个等级逐级发放，每个等级只发一次；重播动画不写奖励。

星光投入先选择数量，再确认。单次1–50颗，以现有余额、家长自主额度及剩余升级容量为上限。默认发给家长批准，申请不扣星；批准时重查余额。家长可允许日额度内自主培养，超过额度仍需批准。培养批准后不可退款；未批准申请可取消，确认界面提前说明。

本版固定20级，不按日期重置，也没有“季末清空”。各次升级所需星光为：

`5, 8, 12, 16, 20, 24, 28, 32, 36, 40, 44, 48, 52, 56, 60, 60, 60, 60, 60`

这是一套首版配置，不代表已经经过长期家庭试玩的数值平衡。规则带版本号，后续不得直接改表来重新计算已有成长。满级后不再接收星光，保留游戏、作品、装扮和已学本领。

2级开放转圈练习；3级进入新的成长外观并开放物种专属动作；4级开放收纳练习；6级进入大伙伴外观。原有本领道具仍可以提前开放对应练习。升级只开放本领，练习不另收费；已学会的技能保留。

## 徽章小铺

共29件永久物件/玩法，原有15件保留，再增加5件新装扮、5个新小房子、4件家具。新普通裙子/装扮1枚，独立小房子2枚，其他物品在预览和确认页明确显示徽章价。五个小房子会实际摆进房间；它们和可换的房间背景是不同概念。

小铺默认优先展示裙子与房子。孩子可以免费试穿、预览；确认前显示徽章余额及兑换后余额。所有新物品兑换使用徽章，不扣星光，也不要求星光和徽章同时支付。已有物品不重复购买。

家长在兑换后30秒内可以撤销物品，返还原币种并收回相关摆放；不会倒扣成长。徽章不能兑换回星光。可设一个愿望目标，不自动购买、不冻结余额、不设置到期。

## 老数据如何升级

- 原宠物、名字、作品、相册、家庭媒体、已买道具和习惯均保留。
- 已经长大的旧宠物保留最低外观阶段。新经济等级从1级/0投入开始，不倒退旧形象，不把旧互动次数兑换成免费徽章。
- 已批准的旧星光物件保留所有权和历史星光流水；符合原撤销窗口的历史兑换仍返还星光，而非徽章。
- 未处理的旧星光“物品申请”取消，标注原因、不扣款。孩子到新徽章小铺重新选择，不悄悄改变币种/价格。
- 旧客户端继续用星光买物品时会收到规则升级提示，不暗中执行另一种扣款。
- 数据根结构仍为v7、宠物模块仍为v1，单只宠物新增经济规则v2。导入/服务端写入都进行一致性验证：成长总投入、已批准申请、等级奖励和徽章流水必须对应。

## 视觉与动作

已把本次对话生成的图像拆为53份独立WebP，接入实际页面：30个角色姿态、5颗蛋、星光/徽章2个图标、16个裙子/房子/家具图。五种新图像角色：独角兽、小狗、小兔、九尾狐、小鸡。原来的眠眠熊、云朵、太空猫保留分层矢量形象和动作。

新五种采用一致的六姿态与有限动作，换装叠加实际衣饰，成长出现徽饰/光圈/大小变化；不是每个年龄都新画了一套身体，也不是连续逐帧影片。原矢量三种保留年龄比例变化。这一边界在预览页和素材说明中明确标注。

动作包括选择预览、破壳、喂星光、吃东西、挥手、睡觉、跳跃/物种技能和升级庆祝；支持系统与应用“减少动态”，均非无休止动画。兑换不靠播放完动画才保存；动画失败不影响结果。

复用项目已带有的 Motion mini（MIT）用于有限面板过渡；运行时不从CDN下载，不额外添加多套UI依赖。新增代码与现有CSS动作相互配合。

## 与其他页面和旧宠物功能的关系

今晚任务区域、三列平级任务卡、简洁顶部、原有三主导航和晚安音乐不改变。本次没有重新增加“专注一件”。小游戏、创作草稿、机器人、花园、偏好、本领、画画、媒体归属与家长控制沿用上次已交付实现。

照片与语音仍需家长开启、用户主动选择或录制并确认，不增加对话式AI识别。现实阅读/运动/责任记录与游戏故事分开，不为同一现实事件重复发星光。

## 本机运行及发布

Node.js22.16或以上。应用包内更新脚本之前自行保存本机改动并切到原功能分支；脚本默认仅检查，不切分支，不暂存/提交/推送。

```bash
npm ci
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:pwa
```

前端和后端需要一起升级，不能新前端连旧后端。先备份数据库与媒体，再按原部署流程发布。完整构建产物包含 `sw.js`、`precache-manifest.json` 和 `assets/pets-v2/`；不要只替换HTML或单个脚本。

本次自动测试在合成家庭数据上执行，不读取生产家庭。完整验收结果在交付包 `verification/`，不以历史GitHub绿色检查代替新版本验证。
